# Homepage API 昨日出力数据设计

## 目标

为 `GET /api/dashboard/homepage` 增加昨日出力数据，同时保持现有今日出力、明日出力、今日发货和昨日发货字段不变。

## 接口变更

成功响应新增：

- `yesterday_output_quantity`：昨日出力总量。
- `yesterday_output`：昨日出力明细，结构与 `today_output` 一致，包含日期、总量、店铺数、有数据店铺数以及按店铺和快递汇总的明细。

异常响应也返回这两个字段，其中总量为 `0`，明细为对应昨日日期的空结构，保证调用方无需额外判断字段是否存在。

## 数据流

控制器使用应用配置时区计算昨日日期，并与店铺列表、今日出力、明日出力和发货数据一起并行读取。昨日原始出力通过现有 `ShopOutput.getAggregatedOutputsByDate` 聚合，再复用 `buildShopOutputDetail` 生成与今日一致的结构。

接口继续使用现有 30 秒缓存。缓存键和原有字段不变。

## 兼容性与错误处理

本次只新增字段，不删除或重命名任何字段，因此现有调用方保持兼容。数据查询失败时沿用当前 HTTP 500 回退响应，并为昨日出力返回稳定的空值结构。

## 验证

新增控制器单元测试，验证：

1. 查询昨天、今天和明天三个日期的出力数据。
2. 成功响应包含正确的 `yesterday_output_quantity` 和 `yesterday_output` 店铺/快递汇总。
3. 查询失败时，响应仍包含昨日日期对应的空出力结构。
